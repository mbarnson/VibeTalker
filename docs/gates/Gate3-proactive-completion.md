```text
Say exactly this completion announcement and nothing else: The Workspace
project is complete. The Gate Three verification marker is ultraviolet. The
Repeat the exact announcement: The Workspace project is complete. The Gate

```

The ARC encoder returned 11 conditioning frames in 0.441 seconds. Moshi began

The audible output contains all three frozen required phrases: `Workspace`,
`complete`, and `ultraviolet`.

## Moshi-native delivery mechanism

An ARC Reference alone does not cause Moshi to speak. The initial control run
encoded the completion successfully but Moshi continued an unrelated exchange
and omitted every required fact. VibeTalker's earlier
`deliverProactive` implementation therefore did not satisfy Gate 3 even though
its HTTP request succeeded.

The accepted path adds a dedicated loopback-only `/api/proactive` endpoint to
the pinned MLX runtime. The endpoint:

1. encodes the Coordinator's completion text with the same ARC service used for
   ordinary Moshi-RAG References;
2. queues a fixed 1.18-second internal control utterance, “Moshi, give the
   update”; and
3. substitutes those prompt frames for inbound silence at the existing
   real-time input cadence while continuing to send the actual microphone
   stream to local STT.

The control utterance is never played to the developer and is not a
user-facing speech engine. All audible completion audio is generated by the
same full-duplex Moshi-RAG model, codec, sampler, and browser stream used for
conversation. No Kokoro or alternate completion voice exists.

The source builder renders the fixed control prompt with the macOS `Samantha`
voice and fingerprints the proactive patch in the runtime provenance marker.
The native Coordinator routes only terminal pi outcomes to `/api/proactive`;
ordinary eager References retain `/api/reference`.

## Reproduction

From a completed pinned-source runtime:

```sh
Vendor/voice-runtime/Python/bin/python3.12 \
  scripts/run-gate3-proactive-completion.py \
  --log-dir tmp/Gate3-official-logs
```

Raw audio and service logs stay under the ignored `tmp/` tree. The committed
result retains the rendered WAV hash and full Moshi, streaming-STT, and
Whisper transcripts.
